# JARVIS for Windows

Персональный голосовой ассистент с Gemini Live, локальным пробуждением, управлением Windows, Telegram и музыкальными сервисами.

## Для пользователей

Windows 10/11, 64 бита. Скачайте `JARVIS-Setup-0.17.0.exe` из Releases и установите программу. Альтернатива — ZIP: распакуйте **всю папку** и запустите `JARVIS.exe`. Node.js устанавливать не нужно.

При первом запуске каждый пользователь вводит свой ключ Gemini и самостоятельно подключает Telegram и музыку. Чужие ключи, переписки и авторизации в дистрибутив не входят. Личные данные хранятся отдельно в `%APPDATA%\JARVIS`; секреты шифруются средствами Windows для текущего пользователя.

Обновления находятся в **Настройки → Обновления JARVIS**. Проверка запускается после старта программы и затем каждые шесть часов. Новая версия скачивается в фоне, проверяется по SHA-256 и включается при следующем перезапуске. Автоматическую загрузку можно выключить. До первой публикации GitHub будет сообщать, что релизов ещё нет.

Discord пока управляется через его приложение. Telegram работает через API, в том числе когда Telegram Desktop закрыт.

## Сборка

На Windows с Node.js 24:

```powershell
npm install
npm ci --prefix telegram-runtime --ignore-scripts
npm test
npm run build:win
```

Сборка использует локальную копию Electron, библиотеки Telegram и модель `public/models/ru-small.tar.gz`. Результат: установщик, переносимый ZIP и манифест `dist/jarvis-update.json`. `dist/build-audit.json` содержит список упакованных файлов. Профили, ключи, история, логи и тестовые данные исключаются явным списком файлов.

Исходная рабочая папка разработчика использует прежний профиль `runtime/desktop-profile`. Установленная или переносимая сборка использует `%APPDATA%\JARVIS` и начинает с отдельного профиля. Первый переход с рабочей папки на дистрибутив требует указать свои подключения заново; прежний профиль остаётся на месте.

## Публикация обновления

При первой публикации загрузите в релиз `v0.17.0` установщик, ZIP, `jarvis-update.json` и файл `ru-small.tar.gz` из `public/models`. Модель нужна для последующих сборок в GitHub Actions; её контрольная сумма закреплена в workflow.

Для следующего выпуска измените версию в `package.json`, проверьте изменения и отправьте тег вида `v0.17.1`. Workflow `release.yml` соберёт и опубликует дистрибутивы. В нём используется временный токен GitHub Actions; токены GitHub не включаются в приложение. Пользователям доступны публичные Releases без авторизации.

Адрес обновлений по умолчанию задаётся в `release-config.json`. В GitHub Actions он берётся из адреса текущего репозитория. Перед выпуском убедитесь, что репозиторий принадлежит вам.

Бинарные файлы не подписаны сертификатом издателя. Установщик создан локально и пока не прошёл отдельную проверку на чистой машине.
